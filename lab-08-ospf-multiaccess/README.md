# Лаба: OSPF с множественным доступом (выборы DR/BDR)

**Инструменты:** Cisco Packet Tracer, CLI Cisco IOS
**Курс:** «Компьютерные сети», лабораторная №13 (вариант 14)

## Что сделано
- Построена multi-access топология: 3 роутера в общей сети 175.133.1.0/24
- Явно заданы Router ID (команда router-id)
- Исследованы выборы DR/BDR: при равных приоритетах (1) роли
  определились по Router ID и порядку настройки
  (R3 → DR, R2 → BDR, R1 → DROther)
- Изменены приоритеты (255 / 100 / 0) с перезапуском интерфейсов:
  R1 с priority 255 стал DR несмотря на наименьший ID,
  R2 с priority 0 исключён из выборов
- Проверены смежности show ip ospf neighbor (все FULL/DR, FULL/BDR,
  FULL/DROTHER) и взаимодостижимость (ping, traceroute)

## Ключевые наблюдения
- Приоритет интерфейса важнее Router ID при выборах DR/BDR
- Priority 0 принудительно исключает роутер из выборов
- DR/BDR уменьшают число смежностей в сегменте: вместо «все со всеми»
  каждый роутер держит полную смежность только с DR и BDR

## Связь с кибербезопасностью
- DR управляет обменом LSA в сегменте: злоумышленник, ставший DR,
  контролирует маршрутную информацию всего сегмента. Поэтому роли
  DR/BDR нужно задавать явно (priority), а не оставлять на самотёк.
- Hello-пакеты OSPF не защищены по умолчанию → возможен rogue router
  в сети. Защита: аутентификация OSPF + priority 0 на портах,
  куда могут подключиться чужие устройства.
- show ip ospf neighbor — инструмент детекции: неожиданный сосед
  в таблице = индикатор атаки на маршрутизацию.
