# Лаба: Настройка параметров OSPF

**Инструменты:** Cisco Packet Tracer, CLI Cisco IOS
**Курс:** «Компьютерные сети», лабораторная №11 (вариант 23)

## Что сделано
- Настроены интерфейсы; сняты таблицы маршрутизации ДО запуска OSPF
  (только C — connected-маршруты) и ПОСЛЕ (появились O-маршруты, AD 110)
- Настроен OSPF на всех маршрутизаторах, разобрана роль backbone-зоны
  и межобластной маршрутизации (ABR, LSA type 3, суммаризация)
- Проверено правило выбора Router ID (максимальный активный IP)
  через show ip protocols
- Разобраны три базы OSPF: смежности (neighbor), топология (LSDB),
  маршрутизация (show ip route)
- Изменена стоимость интерфейса (ip ospf cost), показано влияние на выбор пути
- Сравнены таблицы маршрутизации RIP и OSPF
- Исследованы нештатные ситуации: отключение одного линка
  и полная изоляция узла

## Ключевые наблюдения
- При отказе одного канала OSPF автоматически перестроил маршруты
  через обходной путь — связность сохранилась
- При полной изоляции узла маршруты до него были корректно удалены
  из таблиц, а не оставлены «в никуда»
- Полный цикл состояний соседства: Down → Init → Two-Way →
  ExStart → Exchange → Loading → Full

## Связь с кибербезопасностью
- OSPF без аутентификации принимает в область любой роутер:
  злоумышленник может шлать ложные LSA и перенаправлять трафик
  (OSPF spoofing). Митигация — OSPF authentication (MD5/SHA),
  passive-interface на «смотрительных» портах.
- Понимание LSDB и типов LSA (1/2/3) нужно, чтобы замечать
  аномальные анонсы в сети — признак атаки на маршрутизацию.
- Автоперестроение маршрутов при отказе = доступность (availability),
  одна из трёх основ ИБ (CIA).
- RIP против OSPF: RIP проще подделать (в v1 нет аутентификации),
  у OSPF ниже AD (110 против 120) и метрика на основе пропускной
  способности, а не числа хопов.
